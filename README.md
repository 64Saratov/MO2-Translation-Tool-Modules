# MO2TT upstream modules — candidate modules for 3.5.0 integration

Три автономных модуля из MO2 Translation Tool — Community Fork (3.3.1),
подготовленные для интеграции в чистую кодовую базу оригинала (InfernoKgn).
Только стандартная библиотека Python. Нет зависимостей от Qt и mobase —
модули можно импортировать в любой код плагина MO2.

## text_protect.py — защита нетранслируемых фрагментов

Проблема: LLM меняет одиночные символы внутри тегов (`<font>Y</font>` →
`<font>Д</font>`), теряет форматные токены и брейсы.

API:
- `make_protector(prefix="⟦", suffix="⟧")` → `(protect, restore)`.
  Одна пара — на один запрос/поток: `protect(text)` заменяет защищаемые
  фрагменты плейсхолдерами ⟦N⟧, `restore(text)` возвращает их на место.
- `check_placeholders(src, dst)` → `(ok, lost)` — пост-проверка: сравнение
  мультимножествами, два `%d` в исходнике требуют двух `%d` в переводе.
- `has_missing_placeholders(src, dst)` → bool.

Порядок проходов внутри `protect()`: одиночные буквы между скобками
(`>Y<`) защищаются ПЕРВЫМИ, до тегов — иначе жадное сопоставление тегов
склеивает фрагменты в фиктивный тег. Покрываются: `%d`, `%s`, `%1$s`, `%%`,
`{0}`, `{player.name}`, литеральный `\n`, теги `<b>`, `</font>`, `<br/>`,
`<font color="red">`. Повторный `protect()` защищённого текста безопасен.

Точка интеграции: до отправки батча в LLM (`protect`) и сразу после
получения ответа (`restore`, затем `check_placeholders`; при потере
токенов — ретрай батча).

## glossary.py — глоссарий как последняя инстанция

Проблема: термин из глоссария в переводе от LLM может прийти нетронутым.

API: `build_matcher(glossary)` → `apply(text)`.

Свойства: длинные термины раньше коротких («Dark Brotherhood» не даёт
двойного «Братства»); замены по границам слов, без учёта регистра;
однопроходность — вставленный перевод не сканируется повторно.

Точка интеграции: в worker после получения ответа LLM (не только на ветке
кэша) — `apply(dst)`.

## scanner_status.py — coverage-детекция статуса перевода

Проблема: эвристика «есть кириллица → переведено» даёт ложные срабатывания
(имя NPC «Иван», один переведённый заголовок).

API: `classify_status(en_values, ru_values, threshold=0.6, min_sample=8)`
→ `"translated" | "partial" | "not_translated" | "empty"`.

Логика: сравнение RU-значений с EN-оригиналами по общим ключам; доля
изменённых строк ≥ threshold → «translated»; ≥ 3 изменённых или ≥ 15 %
→ «partial». Caller отвечает за выравнивание значений по общим ключам.

Точки интеграции: глубокий скан статусов в таблице модов; пересчёт статусов
после «Сохранить вывод».

## Пороги

`threshold = 0.6` и `min_sample = 8` — стартовые значения «с запасом»:
при реальных прогонах стоит подстроить по фактуре (сколько строк в
типичном моде). Оба передаются параметрами, менять код не нужно.

## Тесты

`test_modules.py` — 18 кейсов, включая регресс жадного тега (`>Y< and >Z<`),
мультимножество плейсхолдеров, кейс «Иван среди 200 английских строк».
Запуск: `python test_modules.py`. Все кейсы зелёные на момент отправки.
